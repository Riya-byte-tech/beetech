# Honey Chain — MVP Scope Decision

The research phase (see the other documents in this folder) covers the full
Honey Chain ecosystem. This document narrows that down to what an SIH
prototype should actually build. The goal at this stage is not a
production-ready national platform:

> **Build a small, believable vertical slice that demonstrates the core
> value of Honey Chain end-to-end.**

## MVP flow

```text
             🍯 HONEY CHAIN MVP

        BEEKEEPER / DEMO DATA
                 │
                 ▼
          ┌───────────────┐
          │ Hive Dashboard│
          └───────┬───────┘
                  │
             IoT / Mock IoT
                  │
                  ▼
          Health + Yield AI
                  │
                  ▼
            HARVEST EVENT
                  │
                  ▼
            HONEY BATCH
                  │
                  ▼
          BLOCKCHAIN RECORD
                  │
                  ▼
              QR CODE
                  │
                  ▼
             CONSUMER
                  │
                  ▼
       "Verify this honey"
```

This is enough to demonstrate all three major PS requirements without
implementing the entire ecosystem.

---

# 1. What the MVP must demonstrate

PS 26021 reduces to three demo capabilities.

### Capability 1 — Traceable honey batch

A beekeeper creates a harvest:

```text
Hive H-001
Harvest: 8 kg
Date: 05 Sep 2026
Location: Pune
```

That creates:

```text
Batch HC-2026-001
```

The batch gets recorded on the blockchain.

### Capability 2 — Smart hive

The dashboard receives:

```text
Temperature
Humidity
Weight
```

Simulated/recorded IoT data stands in for a full physical IoT deployment at
this stage. Then:

```text
sensor data
     ↓
AI/ML
     ↓
Hive Health Score
+
Yield Prediction
```

### Capability 3 — Consumer verification

Generate a QR code for:

```text
Batch HC-2026-001
```

Scanning it opens:

```text
Honey Chain

✓ Verified Batch

Producer: Verified beekeeper
Origin: Pune, Maharashtra
Harvest date: 05 Sep 2026
Source Hives: H-001
Quantity: 8 kg

Processing: Demo Processing Unit
Quality Check: Passed*
Blockchain Record: ✓

[View Traceability]
```

That is a complete story end to end.

When the batch is created:

```text

       ↓

       ↓
Transaction hash
```

The UI shows:

```text
Blockchain Status
──────────────────
✓ Batch registered
✓ Source hive linked
✓ Harvest timestamp stored
✓ Record immutable

TX:
0x8f3a....92c1
```

A gigantic blockchain system isn't necessary for the MVP — only proof that:

> **A traceability event was written to a blockchain and can be
> independently verified.**

This is where the MVP can look bigger than it actually is.

```text
    ↓
✓ Received at processing unit
    ↓
✓ Quality test recorded
    ↓
✓ Processed
    ↓

    ↓
```

Each is an event. The user sees:

```text
          TRACEABILITY

          │

          │
07 Sep ─ Processed
          │
07 Sep ─ Packaged
```

# 6. No real laboratory needed for the MVP

An important scope decision. For the demo:

```text
Quality Test

Moisture       18.4 %
HMF            32 mg/kg
C4 Sugar       3.1 %

Status: PASS
```

Clearly labeled as a **demo / simulated laboratory record** — generated
values must never be presented as actual laboratory results. The point of
this feature is to demonstrate the data flow:

```text
Lab record
    ↓
Certificate/document
    ↓
Hash
    ↓
Blockchain
    ↓
QR
```

not to claim the prototype is an accredited food laboratory.

# 8. Keeping the AI narrowly scoped

Three research-grade AI systems are not necessary. For the MVP:

### AI #1 — Hive anomaly / health score

Inputs:

```text
Temperature
Humidity
Weight
```

Output:

```text
Health Score: 82/100
Status: Healthy
```

A simple rules-based or rules-plus-ML approach is sufficient, depending on
available data.

### AI #2 — Honey yield prediction

Inputs:

```text
Historical weight
Temperature
Humidity
Season
Hive history
```

Output:

```text
Expected yield: 8.2 kg
```

That's sufficient for the MVP.

### Disease detection

Full disease classification is left out of the MVP scope unless a suitable
dataset/model already exists. Instead:

```text
⚠️ Abnormal hive pattern detected.
Inspection recommended.
```

This is easier to defend scientifically than a disease-name diagnosis.

---

# 9. Keeping the IoT prototype simple

Fifty smart hives are not required — one physical prototype is enough:

```text
ESP32
 ├── DHT22
 │    ├── Temperature
 │    └── Humidity
 │
 └── Load Cell
      └── Hive Weight
```

Then:

```text
ESP32
  ↓
Wi-Fi
  ↓
FastAPI / MQTT
  ↓
Database
  ↓
Dashboard
```

A **Simulation Mode** should also exist for the demo — hardware can fail
minutes before judging, and the demo should not depend on it working.

# 13. Building the MVP for extensibility

The MVP should be built so these can be added later without a rewrite:

```text
MVP
 │
 ├── Madhukranti integration
 ├── KVIC integration
 ├── real laboratory APIs
 ├── real FPO marketplace
 ├── more sensors
 ├── disease models
 ├── multilingual app
 ├── offline-first mobile
 ├── cluster analytics
 └── nationwide deployment
```

None of these need to exist now. The architecture merely shouldn't prevent
them later.

---

# 14. MVP definition

> ### **Honey Chain MVP**
>
> A prototype that allows a verified beekeeper to monitor a hive using
> IoT/simulated data, receive AI-assisted hive insights, record a honey
> harvest, create a traceable batch, record its subsequent processing and
> quality events, anchor those events to a blockchain, and allow a consumer
> to scan a QR code to verify the batch's provenance.

This is an achievable MVP that satisfies the spirit of every major
requirement in PS 26021. The prior research gives it a solid basis:
Madhukranti provides the precedent for beekeeper/honey-chain registration,
KVIC Honey Mission provides the beneficiary/beekeeping context, FSSAI
provides the quality-data vocabulary, and GS1's event-based traceability
model gives a defensible way to structure the batch journey.

From this point, "full Honey Chain" (see `docs/final-architecture.md`) is the
future roadmap; this vertical slice is Team Odysseus' actual current product.
